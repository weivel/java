The Java language implementation of weivel, for a host written in Java that runs plugins written in Java. It is one of the language implementations the core's contract describes (the core's `docs/contract/`), held to that contract and to the layer vectors of the conformance kit, and it decides nothing itself: compatibility, order, reach, waiting and revocation are the core's answers, made once in C so every language sees the same decisions. It is not the core, and it carries no C. It reaches the core's binary through one native seam in `com.weivel.core`, loading it from the path its caller gives, so one build of the layer runs against whichever core binary its caller loads. The jar is multi-release: on Java 22 and later the seam is Java's foreign function and memory API, on Java 8 to 21 it is JNA, chosen by the Java that runs it with no flag. Both read every struct through one table of offsets written by hand, which the tests compare field by field with what the C compiler laid out. It forces no path, file name, variable or format on its caller. Its parts are the modules every language implementation holds, one package each, and they stand on one another in one direction: `core` makes every call into the core through one wrapper, and because the core never calls out, that wrapper drains the events each call queues and dispatches them to Java listeners itself; `handles` maps the core's integer handles to Java objects; `timer` hands the core the time, since the core owns no clock; `context` is what a plugin sees, built on those three; and `host` loads Java plugins and C libraries through the contexts. `standard`, optional, reads the standard's defaults, and no class of the five depends on it; `conformance` drives the kit's layer vectors through the host, and `benchmarks` times calls through weivel against the same calls made bare. What a process needs to use the layer is in [using.md](using.md), and building it and running its tests and benchmarks in [building.md](building.md).
